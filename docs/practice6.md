# Практическая работа 6 — система бронирования фотостудии FocusFrame

## Что изменено

- На 360 px используется одна колонка, нижняя навигация и карточки записей.
- На 768 px — боковая навигация без подписей, карточки и две колонки главной.
- На 1280 px — таблицы с прокруткой по двум осям и боковая навигация с подписями.
- На 1920 px рабочая область ограничена 1440 px, формы — 760 px.
- Панели фильтров сворачиваются на небольших экранах, раскрытые фильтры имеют
  собственную прокрутку. Кнопки действий карточек находятся под текстом.
- Длинные имена и названия обрезаются многоточием. Состояние списка сохраняется
  при изменении ширины окна, перезагрузка не нужна.
- До первого кадра Flutter видны название фотостудии, индикатор и сообщение.
  Если загрузка не удалась, доступна повторная попытка.
- Редко используемые ролевые разделы загружаются через `deferred as`.
  Из релиза удаляются отладочные
  символы и неиспользуемый skwasm-рендерер обычной JS-сборки. Для HTTP создаётся gzip.

## Сборка и локальный запуск

```powershell
flutter pub get
flutter build web --release --no-web-resources-cdn --dart-define=API_BASE_URL=/api
node scripts/optimize-web.js build/web
$env:STATIC_DIR = (Resolve-Path build/web).Path
node server/mock-server.js --port 8080
```

Открыть `http://localhost:8080`. Клиент и API работают с одного источника.
Адрес API задаётся во время сборки, а относительное `/api` подходит для Render.
Для отдельного Flutter debug-сервера:

```powershell
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://localhost:8080/api
```

WebAssembly и JS fallback:

```powershell
flutter build web --release --wasm --no-web-resources-cdn --dart-define=API_BASE_URL=/api
```

Для размещения в подкаталоге нужен `--base-href /photostudio/` и соответствующее
сопоставление пути на хостинге. На Render приложение размещается в корне `/`.

## Render

`Dockerfile` собирает Flutter 3.27.2, затем переносит только веб-релиз и Node API
в итоговый образ. `render.yaml` описывает бесплатный Web Service без СУБД.
Один HTTPS-адрес исключает смешанное HTTP/HTTPS-содержимое и необходимость CORS
между клиентом и API. `PORT` задаёт Render. Секрет подписи токенов задаётся
переменной `JWT_SECRET`, исходный код не содержит постоянного ключа подписи.

Сервер выдаёт `index.html` для `/halls/12`, `/bookings/new` и других маршрутов
Flutter, поэтому прямые ссылки и обновление страниц не дают 404. Отсутствующий
JS-файл возвращает настоящий 404. У `.wasm` правильный MIME-тип. Заголовки
COOP/COEP поддерживают Wasm; gzip уменьшает объём передачи.

Автопроверки и обе сборки: `.github/workflows/verify.yml`. Автопубликация Render
настроена на изменения `main` после успешных проверок (`checksPass`).

На бесплатном Render файловая система временная: после перезапуска или
повторного развёртывания записи и регистрации возвращаются к демонстрационным.
СУБД на этом этапе не подключается. Бесплатный сервис засыпает после простоя;
первое обращение после простоя требует времени на запуск.

## Тесты

`test/practice6_test.dart` содержит восемь модульных проверок: обязательное
название, непустое название, вместимость, почта, неполный JSON, преобразование
чисел, ограничения менеджера, право клиента на собственное бронирование.

Виджетные проверки: 13 экранов × 4 ширины; переключение ширины без потери
выделения; состояние загрузки; пустой список; ошибка и повторное подключение;
валидация входа; скрытие административных действий для клиента.

`server/static-files.test.js` проверяет прямые ссылки, MIME, gzip, HEAD,
отсутствующие файлы, ограничение путей и методы HTTP.

```powershell
flutter test
flutter analyze
dart format --output=none --set-exit-if-changed lib test
node server/test-api.js
node server/test-auth.js
node server/test-booking-roles.js
node --test server/static-files.test.js
```

Сравнение сборок: `node scripts/measure-web.js build/web`. `rawBytes` — сумма
исходных файлов; gzip-копии не считаются вторым комплектом приложения.
`gzipTransferBytes` — теоретический объём передачи всех файлов с gzip, а не
объём первой загрузки: браузер загружает только нужные ему рендерер и код.

Измеренные результаты и снимки добавляются после завершения сборок и проверки
в браузере; они не подменяются оценками.
